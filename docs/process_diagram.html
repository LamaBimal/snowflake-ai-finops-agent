Snowflake AI FinOps Agent — How the Process Works

Detects abnormal Cortex AI token and credit usage, identifies the root cause from evidence, explains it with Cortex AI, and recommends fixes that are checked against cost and quality. Everything runs inside the AI_FINOPS database.

The three questions it answers

1. Did AI cost behave abnormally?Rolling 7-day Z-score on 9 daily metrics per application, with Isolation Forest as a second detector.
2. What caused it?Ordered, deterministic rules on before/after evidence. The LLM never decides the cause.
3. What should change, and is it safe?Playbook action + simulated saving + measured quality impact for model changes.

One daily run, step by step
  1. Recompute daily metrics per app from Cortex usage (views, always current).
  2. Score the last 3 days against each app's 7-day baseline; store WARNING/HIGH rows.
  3. Group consecutive flagged days into incidents starting at the first HIGH day.
  4. Apply rules to before/after evidence → root cause + confidence.
  5. Ask Cortex to explain new incidents using only the evidence and playbook.
  6. If new usage arrived, retrain Isolation Forest as a second opinion.

Design principles

Deterministic before LLMStatistics and rules find the anomaly and its cause; Cortex only turns evidence into readable text with a fixed JSON schema.
Cost is checked against qualityRouting recommendations come from measured accuracy on a validated ticket set, not from model size or price alone.
Every recommendation is explainableProblem, evidence, action, saving estimate (computed in SQL), quality risk, and confidence.

Known limitations

  • Results come from synthetic data; real Cortex usage in this account is small and mostly untagged.
  • Quality impact is measured only for model changes; other fixes are assumed quality-neutral.
  • AI-function latency is not available (usage history is in hourly buckets); Cortex Agent latency is captured when agents are used.
  • Cortex Agent and Cortex Search views are wired in but currently empty in this account.
  • Model credit rates rest on a few billed calls and sharpen as ACCOUNT_USAGE catches up.
